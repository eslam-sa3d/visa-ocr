# API examples and sample data

Generated by `tools/make_samples.py` from the running service. All people are fictional and all numbers are made up.

## 1. Upload a document

Send 1 to 4 JPEG or PNG images (for example the passport data page). The call returns immediately with a job.

```bash
curl -X POST https://ocr.internal.example/v1/documents/extract \
  -H 'X-Correlation-ID: portal-req-0001' \
  -F 'files=@data-page.jpg;type=image/jpeg' \
  -F 'doc_type_hint=passport'

# Poll for the result:
curl https://ocr.internal.example/v1/jobs/7f3c2a9e1b4d4c6a8e5f0b1d2c3a4b5e
```

Response `202 Accepted`:

```json
{
  "jobId": "7f3c2a9e1b4d4c6a8e5f0b1d2c3a4b5e",
  "status": "queued",
  "correlationId": "portal-req-0001"
}
```

## 4. Failures

No MRZ found in the image (job status `failed`):

```json
{
  "jobId": "7f3c2a9e1b4d4c6a8e5f0b1d2c3a4b5e",
  "correlationId": "portal-req-0001",
  "status": "failed",
  "createdAt": "2026-11-09T09:52:14.512345+00:00",
  "result": null,
  "error": {
    "code": "mrz_not_found",
    "message": "No MRZ and no ID-card fields could be read. For a passport or visa, retake the photo flat and sharp with the two long lines of '<' at the bottom fully visible. For a card, include the whole front.",
    "retake": {
      "recommended": true,
      "reasons": ["not_found"],
      "message": "The document could not be read from this photo. Take the photo again: show the page with the two long lines of letters and '<' (for a card, the side that has them), flat, in focus and in good light, filling the frame."
    }
  }
}
```

### Asking the applicant for another photo

Whenever the applicant should take the photo again, the response carries a `retake` block. **Show `retake.message` to the applicant.** It appears in three places:

| Where | When | Job status |
|---|---|---|
| `detail.retake` on the upload call, HTTP 422, code `image_unclear` | The photo is plainly unusable (blurred, too dark, washed out, too small, blank). Refused at once, on the upload itself: no job is created, whatever the load. | no job |
| `error.retake`, code `image_unclear` | The photo is plainly unusable (blurred, too dark, washed out, too small, blank). Only when `UPLOAD_CLARITY_CHECK=0`: turned back before any reading, as a failed job. | `failed` |
| `error.retake`, code `mrz_not_found` or `image_unclear` | Nothing could be read from the photo. | `failed` |
| `error.retake`, code `multiple_documents` | The photo shows more than one document with machine-readable lines. Nothing is read from it. | `failed` |
| `result.retake` | An MRZ was read but a check digit fails, or a card's ID number could not be read. The reading is still returned for the reviewer. | `done`, `needsReview: true` |
| `result.retake`, flag `page_cut_off` | A passport's MRZ was read and its check digits pass, but most of the page above it is outside the photo. The reading is still returned for the reviewer. | `done`, `needsReview: true` |

`retake.reasons` lists why, most serious first: `blurred`, `too_dark`, `too_bright`, `low_contrast`, `too_small`, `mrz_unclear`, `card_unclear`, `not_found`, `page_cut_off`. A reading whose check digits all pass carries `retake` only for a cut-off page, however the photo looks.

Unusable photo, refused on the upload call (`POST /v1/documents/extract` answers HTTP 422, no job is created):

```json
{
  "detail": {
    "code": "image_unclear",
    "message": "The photo is blurred. Hold the phone steady, wait for it to focus on the document, and take the photo again.",
    "retake": {"recommended": true, "reasons": ["blurred"], "message": "The photo is blurred. Hold the phone steady, wait for it to focus on the document, and take the photo again."},
    "quality": {"clear": false, "width": 1920, "height": 2560, "sharpness": 6.2, "brightness": 141.0, "contrast": 31.5, "glare": 0.0, "issues": ["blurred"], "doubts": []}
  }
}
```

Unusable photo with `UPLOAD_CLARITY_CHECK=0`, or a photo that could not be read (job status `failed`):

```json
{
  "status": "failed",
  "result": null,
  "error": {
    "code": "image_unclear",
    "message": "The photo is blurred. Hold the phone steady, wait for it to focus on the document, and take the photo again.",
    "retake": {"recommended": true, "reasons": ["blurred"], "message": "The photo is blurred. Hold the phone steady, wait for it to focus on the document, and take the photo again."},
    "quality": {"clear": false, "width": 1920, "height": 2560, "sharpness": 6.2, "brightness": 141.0, "contrast": 31.5, "glare": 0.0, "issues": ["blurred"], "doubts": []}
  }
}
```

### Check a photo before sending it

`POST /v1/documents/check` with one image in the `file` field answers at once from the pixels alone. Nothing is read, stored or queued, so the portal can call it the moment the applicant takes the photo.

```json
{
  "clear": false,
  "acceptable": false,
  "quality": {"clear": false, "width": 1920, "height": 2560, "sharpness": 6.2, "brightness": 141.0, "contrast": 31.5, "glare": 0.0, "issues": ["blurred"], "doubts": []},
  "retake": {"recommended": true, "reasons": ["blurred"], "message": "The photo is blurred. Hold the phone steady, wait for it to focus on the document, and take the photo again."}
}
```

`acceptable: false` means the extract call would turn this photo back: ask for another one. `acceptable: true` with `clear: false` is a soft photo that may still read. This check sees the whole photo only: glare over a few MRZ characters or a cut-off MRZ passes here and is caught by the reading, so always handle `retake` in the job result too.

### Passports only: read the MRZ of a passport

`POST /v1/passports/extract` takes the same upload as `POST /v1/documents/extract` (the `files` field, the optional
`expected_*` fields and `consent_training`) and answers the same way: HTTP 202 with a `jobId`, then `GET /v1/jobs/{id}` for
the result, in the same shape. It differs in one thing: it accepts nothing but the machine-readable zone of a passport.

| What is uploaded | Job result |
|---|---|
| A passport page with its MRZ | `done`, the passport's fields and check digits |
| A visa, an ID card or a residence permit with an MRZ | `failed`, code `not_a_passport` |
| A card front or any page with no MRZ | `failed`, code `mrz_not_found` (or `image_unclear`) |
| Two documents in one photo | `failed`, code `multiple_documents` |

Every failure carries `error.retake.message` for the applicant. `POST /v1/documents/extract` is unchanged and still reads
every kind of document.

```json
{
  "status": "failed",
  "result": null,
  "error": {
    "code": "not_a_passport",
    "message": "This is not the photo page of a passport. Take a photo of the passport page that shows your photo and has two long lines of letters and '<' at the bottom.",
    "retake": {"recommended": true, "reasons": ["not_a_passport"], "message": "This is not the photo page of a passport. Take a photo of the passport page that shows your photo and has two long lines of letters and '<' at the bottom."}
  }
}
```

### Check the applicant's personal photo

`POST /v1/photos/check` with one image in the `file` field answers at once (well under a second) whether the photo can be
used. Nothing is stored or queued, and the face is not compared with anything: the check says whether the photo meets the
rules, not whose face it shows.

```json
{
  "acceptable": false,
  "issues": ["background_not_plain"],
  "doubts": [],
  "measures": {"width": 600, "height": 750, "faces": 1, "faceHeight": 0.24, "faceCentre": 0.39, "faceSharpness": 54.8, "faceBrightness": 155.6, "backgroundBrightness": 176.0, "backgroundSpread": 44.2, "eyes": 2, "tiltDegrees": 3.7},
  "messages": ["The background is not plain. Stand in front of a plain white or light wall, with nothing behind you, and take the photo again."],
  "retake": {"recommended": true, "reasons": ["background_not_plain"], "message": "The background is not plain. Stand in front of a plain white or light wall, with nothing behind you, and take the photo again."}
}
```

`acceptable: false` means refuse the photo and show `retake.message`. `issues` refuse the photo; `doubts` do not.

| Code | Kind | Meaning |
|---|---|---|
| `unreadable`, `too_small`, `wrong_shape` | issue | The file does not open, is under 300 pixels on its short side, or is not a portrait (taller than wide, up to square) |
| `no_face`, `several_faces` | issue | No face seen from the front, or more than one |
| `face_cut_off`, `face_too_small`, `face_too_close`, `not_centred` | issue | The face touches the edge, is under 20% or over 72% of the photo's height, or is far from the middle |
| `blurred`, `too_dark`, `too_bright` | issue | The face is out of focus, dark, or washed out |
| `background_not_light`, `background_not_plain` | issue | The background is dark, or has objects or patterns in it |
| `eyes_not_clear`, `head_tilted`, `not_colour` | doubt | Both eyes were not found (glasses, hair, closed eyes), the head slopes more than 12 degrees, or the photo is black and white |

Every limit can be set (`PHOTO_MIN_SIDE`, `PHOTO_FACE_MIN`, `PHOTO_BACKGROUND_LIGHT` and so on; see `photo_thresholds` in
`app/config.py`). HTTP 503 with code `photo_check_unavailable` means the face detector is missing on that host.

Rejected upload (HTTP 415):

```json
{
  "detail": {
    "code": "bad_type",
    "message": "Only JPEG and PNG are accepted"
  }
}
```
